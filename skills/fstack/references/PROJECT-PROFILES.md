# PROJECT-PROFILES: adapting the convention to a project

> The convention is the same everywhere, its filling changes. A profile says what SETUP creates
> and what the `contexte:convention` block must declare. Size is measured separately, it does not
> depend on the profile.

## Detecting the profile

Without a block in `CODEMAP.md`, SETUP deduces the profile from the files present, takes the
dominant one and notes the others in the block. When in doubt, it asks.

`ctx-init.sh` tests in this order, from most specific to most general: a game engine or a mobile
app also carries a `package.json` or a `Packages/` folder, so it comes before app and monorepo.
Folder names are compared case-insensitively, because macOS answers yes to `packages/` for
Unity's `Packages/`.

| Hints | Profile |
|---|---|
| `.claude-plugin/plugin.json`, `skills/*/SKILL.md`, `SKILL.md`, `.claude/skills/` | outillage-agent |
| `ProjectSettings/ProjectVersion.txt` (Unity), `project.godot`, `*.uproject` (Unreal) | jeu |
| `pubspec.yaml` (Flutter), `android/` and `ios/` together, `*.xcodeproj`, `app/src/main/AndroidManifest.xml` | mobile |
| `pnpm-workspace.yaml`, `turbo.json`, `go.work`, `nx.json`, `lerna.json`, `packages/`, `apps/` | monorepo |
| `src-tauri/`, `electron` in `package.json` | desktop |
| `terraform/`, `ansible/`, `k8s/`, `*.tf`, `Chart.yaml` | infra |
| `notebooks/`, `*.ipynb`, `dvc.yaml` | data |
| `Cargo.toml` with `src/lib.rs` and no `src/main.rs`, `package.json` that exports with no `start` or `dev` script | lib |
| `package.json`, `pyproject.toml`, `go.mod`, `Cargo.toml`, `manage.py`, `pom.xml`, `build.gradle`, `composer.json`, `Gemfile`, `mix.exs`, `Package.swift`, `deno.json`, `CMakeLists.txt`, `*.sln`, `*.csproj`, `requirements.txt` | app |
| `content/`, `posts/` | contenu |
| `.gitmodules` with equipped children | parent with submodules |
| no code, documents and follow-up | non-technique |

## Size

Counted in files, excluding dependencies, builds and `archives/`. The audit measures it,
`ctx-init.sh` does not write it. Only `taille-forcee:` exists, set by the upgrade when the operator
keeps a value that differs from the measurement (see `PROJECT-CONFIG.md`).

| Size (`taille-forcee:` value) | Files | SETUP creates |
|---|---|---|
| small (`petite`) | under 150 | a single level, no zone |
| medium (`moyenne`) | 150 to 600 | zones where the root map overflows |
| large (`grande`) | over 600 | zones from the start, the root map is only an index |

## Profiles by nature

**New project.** No code, no history. SETUP creates the short templates and the block, nothing
else. Maps fill in over sessions, not in anticipation.

**Existing, documented elsewhere.** README, wiki, `memory-bank` folder. SETUP grafts the three
pillars alongside and points the block at what exists. Nothing is dissolved, what is already in
place stays until the operator decides.

**Taking over an unknown project.** SETUP maps from the code and the git history. It writes only
what a command confirmed, the rest becomes questions in `TODOS.md`.

**App.** Module: a layer or a domain. The block declares the start command and the test command.
The map stresses the entry points, the flow of a request and the environment variables.

**Lib.** Module: a subset of the public API. The log is a public deliverable, Keep a Changelog
format, which the `journal:` key declares. The map gives the exported surface.

**Infra.** Module: a deployed component. State lives outside the repo, so the block declares the
authoritative source to query (provisioning state, console). `docs/ops/` is the core, and each log
entry carries its rollback. Never a secret value, only its location.

**Data.** Module: a pipeline stage. The map gives the lineage and the location of artifacts. Any
cited figure carries the date of its run.

**Content.** Module: a section or a channel. Tone and positioning go in `CLAUDE.md`, abandoned
angles in `archives/`.

**Game.** Module: a game system (combat, inventory, interface, AI) or a major scene, not an assets
folder. The block declares the exact engine version (`ProjectSettings/ProjectVersion.txt`,
`project.godot`, the `.uproject`) and the editor-less build command (Unity with `-batchmode`,
Godot with `--headless --export-release`, Unreal through `RunUAT BuildCookRun`). Binary assets are
out of budget and out of review: the map gives their folders, the import pipeline and what
`.gitattributes` puts in LFS. Scenes and prefabs are text generated by the editor: a classic trap,
to write in the map, is editing them by hand with the editor open. Engine caches (`Library/`,
`Temp/`, `Intermediate/`, `DerivedDataCache/`, `.godot/`) are never context.

**Mobile.** Module: a screen or a feature, rarely a platform. The map separates shared code from
what lives under `android/` and `ios/`. The block declares the minimum SDK versions and each
platform's build command. Certificates, provisioning profiles and keystores never live in the
repo: the map gives their location.

**Desktop.** Module: a process (main and renderer in Electron, Rust core and web view in Tauri) or
a window. The map names the boundary between the two and what crosses it (IPC, commands). Code
signing and auto-update are procedures, they go in `docs/`.

**Monorepo.** Each equipped package keeps its kit, the root points without copying. The block
lists the packages and the zones. See `ZONES.md`.

**Parent with submodules and instances sharing knowledge.** SETUP only touches the parent and
lists the children. See `MULTI-REPO.md`.

**Agent tooling.** Module: a skill, a command or a script. The project applies its own convention.
Verification covers the paths cited from the skill and the executable scripts.

**English project.** The block declares `langue: en`, SETUP creates the templates with English
headers and the audit does not look for French.

**Non-code project.** Module: a workstream. `docs/decisions/` carries the essentials, each
arbitration and stakeholder position is worth an ADR. The log serves as the minutes.

## Adapting without breaking

Three freedoms, all declared in the block: rename (roles matter, not names), merge on a very small
project (the merge is undone as soon as a section exceeds a page), extend with one more pillar if
it answers a question no other covers.

Never adapted, whatever the profile: the resume state block, archiving instead of deletion, the
ban on reading `archives/` as a source of truth, no known-false claim after a debrief.

No external tool is required. A web search or a project tool speeds up a check, a debrief step
never fails for lack of them.
